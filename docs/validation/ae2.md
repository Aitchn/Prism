# Validation: Applied Energistics 2 on Prism

`validation/ae2` rebuilds the core of Applied Energistics 2 as a plain plugin on `prism-api`. It is a **test of Prism**,
not a product: the goal is to find out which parts of a storage-network mod Prism can already express and which parts
it cannot. Textures are placeholders generated by a script; nothing here is published.

## What is implemented

| AE2 feature | Here | Where |
|---|---|---|
| Cables, dense cables, controller | Connectivity, shortest-path channel routing, 8 channels on a cable, 32 on a dense cable, controller conflict detection | `grid/GridCalculator` |
| Power | Idle drain per device, energy cells, creative cell, energy carried across network merges and splits | `grid/PowerState`, `runtime/GridManager` |
| Drives and storage cells | 1k to 256k cells with AE2's byte model (type fee, 8 items per byte, 63 types), 10 per drive, priority | `storage/*`, `Ae2Ui` |
| Terminal | Paged item list, withdraw (1 / 16 / stack), insert held item or whole inventory | `Ae2Ui` |
| Patterns | Blank and encoded patterns, `/ae2 encode` from vanilla recipes, pattern provider block | `crafting/Pattern*`, `Ae2Command` |
| Autocrafting | Recursive planner (stock first, surplus reuse, cycles, missing items), byte cost, jobs on crafting CPUs | `crafting/*` |
| Crafting CPUs | Multiblock cluster of storage blocks and co-processors found by flood fill | `grid/GridCalculator` |

Not attempted: import/export/storage buses, interfaces, P2P tunnels, wireless, spatial storage, facades, cable colours,
security, quartz growth and world generation. Most of them are blocked by the gaps below.

The grid, storage and crafting logic (`grid/`, `storage/`, `crafting/`) does not import Bukkit and has unit tests.
`runtime/` and the top-level classes are the Prism adapter. `-Dae2.selftest=true` places real Prism blocks on a live
server (used by the smoke test) and checks the grid end to end.

## Gaps found

Each gap says what AE2 needed, what was done instead, and what Prism could add. The consolidated list is in
[`docs/gaps.md`](../gaps.md).

### Fixed in this change

- **Block lifecycle.** There was no way to learn that a custom block had been placed or removed, so no network could
  track its members. Added the `BlockPlaceBehavior` and `BlockRemoveBehavior` capabilities, fired from
  `BlockService.place` and `BlockService.remove` (player break, explosions and mod calls all go through them).
  Still missing: the placing player (`place` takes none), chunk load and unload, and changes made by other plugins.

### Open

1. **Per-stack data.** Storage cells and encoded patterns need data on the individual item stack. `ItemService` only
   creates and identifies. AE2 writes its own persistent data container keys on the stack and re-adds lore by hand.
   Prism should offer a typed, per-stack data component (`ItemStack` data with a codec) that survives the per-viewer
   presentation rewrite. Related: there is no "are these two stacks the same item" key; the network keys on the whole
   serialized stack.
2. **Per-block data and enumeration.** There is no per-block data, no list of custom blocks in a chunk and no cleanup
   when a block disappears. AE2 keeps a position index in `DataStore` (`node/…`, `drive/…`, `provider/…`) and cannot
   notice a block removed by WorldEdit. Needed: block-attached data with chunk-scoped load/unload callbacks.
3. **Storage API.** `DataStore` is blocking and string-only. AE2 batches dirty keys and flushes them from an async
   task every two seconds. Needed: async access, multi-key transactions, and a binary value type.
4. **Menus.** `MenuSpec` is a list of buttons. A terminal needed: real slots (insert by dragging), click type (left,
   right, shift), live refresh, text input for search and amounts, and a fixed position for controls. Workarounds: a
   withdraw-amount toggle button, paging buttons, filler panes to push controls to the last row, and re-opening the
   menu after every click, which resets the cursor and flickers. Drive and provider contents are button lists instead
   of inventories.
5. **Block appearance.** A custom block is one static model on a full cube. Cables need a model that changes with
   their neighbours, a thin hitbox and collision, and states such as powered or online. Devices need a facing taken from
   the placer. None of this exists, so every ME block is a plain cube.
6. **Neighbour changes and multiblocks.** There is no neighbour-update callback and no structure helper, so AE2
   recomputes the whole grid on every change and finds crafting clusters with its own flood fill. A `Multiblock` helper
   and a neighbour event would remove most of that code.
7. **Capabilities and transport.** AE2's energy is private to the mod: another plugin's generator cannot feed it, and
   an ME network cannot push into another mod's machine. The pattern provider therefore does not hand items to
   machines; crafting runs inside the CPU. Needed: a capability lookup between blocks (energy, items, fluids).
8. **Recipes and creative inventory.** There is no recipe registry for mod content, so AE2 uses Bukkit recipes and has
   no recipes of its own, and test items come from `/ae2 give`. Prism has no creative tab or item list.
9. **Runtime lookup of definitions.** Reading a component of an item during play (for example how much energy a
   crystal gives) needs the registry; AE2 keeps the `ContentView` snapshot it received. A public lookup on
   `ItemService` would be simpler and survive reloads.
10. **Scheduling across regions.** A network spans regions on Folia, so AE2 never touches the world from its tick and
    guards its state with locks. Prism's `PlatformScheduler` is internal; AE2 uses Paper's global and async schedulers
    directly, which work on Paper, Folia and Purpur (1.20+). This is not a blocker, but the documentation should say
    so and describe the cross-region rule.
11. **Scale.** One display entity per block is fine for tens of ME blocks but not for the thousands a real base has;
    this is the `NativeStateBackend` item already on the roadmap.
12. **Bedrock.** The terminal uses Geyser's translation of the chest menu. It has not been tried on a Bedrock client.

## How to try it

Build and drop `validation/ae2/build/libs/validation-ae2-*.jar` next to Prism, PacketEvents and BetterModel.
`/ae2 give controller`, `cable`, `terminal`, `drive`, `creative_energy_cell`, `storage_cell_4k` and
`blank_pattern`; place a controller, cables and devices so they touch; right-click the drive with a cell in hand,
the terminal to open it. `/ae2 encode` with the target item in the main hand and a blank pattern in the off hand.
